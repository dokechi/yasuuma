# Working first page, inside the paper world

The default is the existing live manuscript owner, not an illustrated landing
screen or a second content preview. Five permanent chapter bookmarks keep the
current work and other accounts reachable on the first screen. Wide layouts bind
the exact existing shelf and a substantial colored illustration leaf beside the
reader; phones retain a compact, recognizable two-color scene above the working
leaf plus explicit shelf/tools controls, never a mandatory full-screen picture. The original five characters, chapter colors and art remain.

## Ownership and meaning

- Initial arrival is passive: no copying, starring, reading acknowledgement,
  visit record, focus transfer, or extra browser-history push. Existing valid
  history/current draft takes priority, then local previous work, then insurance.
- The one desk controller owns current ID, body, filters, scroll, pending updates,
  copy and local records. No backend request or polling is added by this UI.
- Direct chapter bookmarks commit immediately. Empty/loading/error states never
  reuse a previous account's text as the new account's copy target.
- FP/TikTok retained drafts remain available from Settings; they are not mislabeled
  as one of the five publishing/work chapters. Browser Back/Forward and native
  sourcing return use the same existing owner and validated IDs.
- The picture leaf is a modal disclosure. It does not route or replace live text;
  an explicit work button selects a different chapter, and close restores focus.

## Motion without a work barrier

The explicit previous/next page control animates between the four publishing
chapters while the canonical route commits synchronously. Its pointer-inert,
accessibility-hidden paper layer is bounded, interruptible and fails open.
Ordinary bookmarks and reduced-motion paths do not wait for an animation.
Text and action labels remain flat; only paper scenery and the surrounding book
fold. Visible shelf rows are captured with exact scroll extent and coordinates,
not all offscreen records. The original node/text/time budgets remain unchanged.

A restrained ambient paper plant/letter movement follows existing ambiance and
reduced-motion settings, pauses when hidden, away, selecting/typing or in a modal,
and never bobs the character or text. A brief paper-edge response follows only the
existing successful-copy feedback. Sound remains the existing explicit opt-in.

## Acceptance evidence required

Actual production-host fixtures at 320×640, 390×900, 800×648 and 1440×900 must show
useful text and 44px primary actions before any click/scroll, five chapter access,
truthful loading/empty/error/cache states, no passive semantic writes, and retained
source/ID/history/filter/scroll/copy semantics. Optional motion requires real
midframes and ordinary playback, latest-intent interruption, large-list/nonzero
scroll, reduced/hidden/failure paths, and the unchanged native/FP flows.

Unit results are not visual acceptance. Parent and independent QA must inspect
actual first-screen and transition evidence before the exact-head full-CI merge
and public byte/cache/anonymous-entry verification. Physical-device performance
and authenticated production data are not claimed from synthetic CI fixtures.
