`storybook-archive-entry.cjs` performs only normal browser navigation and visible settings/link clicks. Before the click it verifies the real default storybook and no requested archived 3D entry/renderer/model/vendor. Afterwards it verifies the archive URL, the same frame object, the same real iframe node and exactly one host iframe. It never replaces `frame.src`, removes theme classes, changes route owners, injects controller imports, rewrites fixture records, weakens thresholds or catches component failures as successes.

The parent native workspace is styled independently of the child archive. Existing strict same-event native-source → snapshot geometry/material checks remain relevant to its actual surface. Tests must not remove the new parent theme just to force old sourcing image assertions to pass.

The new optional native-header illustration is owned by the storybook presentation. Its real controller observes the current same-origin child presentation: the explicit retained castle does not import or show that new illustration, and returning to the book restores the same decorative instance. Business nodes and the parent theme are not removed. This preserves the archived native snapshot's strict rejection of arbitrary visible images without a test-only style override.

The book's native snapshot may opt in only to its one exact same-origin authored sourcing actor, using a detached image already decoded from the displayed asset. The shared helper independently validates the source/prepared-node pair; other images, active editors, unknown media, over-budget content and unavailable readiness still return no snapshot. The ordinary archived call opts into nothing. The real source DOM, records, selection and scroll remain authoritative; image preparation never reads or writes business data. Actual browser evidence must compare the same-event source and snapshot geometry/material and keep cold fallback distinct from warm motion success.

## New-default release coverage still required

The initial insurance visual slice and preserved archive suites do not satisfy these final gates by themselves:

- All four publishing chapters and native sourcing; eight destinations, three sealed slots and five immediate routes.
- Exact current-account text/copy, variants/replies/images where present, search, shelf/list selection, favorites/history, pending revisions, tools, Back focus and scroll preservation.
- Page/object source geometry, opaque handoff, non-ghosted flat actor/manuscript, corresponding reverse and unpaused completion. The real route must already be usable during presentation.
- Repeated/newer room intent, Back during entry, direct-route bypass, copy/Tab/Escape, parent/child hide, Fold resize and OS/app reduced motion including mid-trip changes. No default sound or replay on resume.
- Missing art/module/CSS keeps existing work usable; no dark old-world fallback on the new default.
- Native ledger/search/tools, actual scroll and current-source values remain unchanged; no synthetic snapshot data, partial manuscript, additional data owner or network mutation.
- Actual host sizes 320×640, 390×900, 800×648 and 1440×900, unchanged readability/touch/overflow thresholds, independent screenshot review, and exact-head CI.

Archived tests retain their original bounds. New visual expectations replace only intentionally redesigned artwork/selectors in new-default suites, never the functional or accessibility requirement itself.
