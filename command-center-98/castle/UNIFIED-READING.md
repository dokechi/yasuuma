# 城下町と読書記録の統一

通常の入口は `entry-v31.html`。旧 `classic` 保存値、旧 HOME 別名、F1 / Alt の入口は城下町または必要な管理機能へ送る。旧 HOME の表示領域は廃止し、管理機能が参照する内部ハンドラーは残す。外部サービスを開いた元のタブは城下町を保つ。

管理原稿は編集・投稿状態確認の役割を維持する。旧読書の検索・印・設定・引き出しは重ねず、コピー通知だけ新しい読書履歴へ渡す。操作中に到着した原稿は明示的な反映待ちにし、読取エラーと利用者自身の更新要求はすぐ表示する。比較機能と元原稿は城下町に残る。

## 保存移行

- 読み取る旧領域は `cc-rpg-daily.v1.` のみ。認証情報など他のキーは収集せず、旧キーは削除しない。
- 原稿照合は `source.account` と `source.id`。先頭の既存 `sns:` 別名だけを正規化する。TikTok と FP は別の媒体として照合する。
- 新キーがあれば `false` も優先。旧印の照合先を保存し、原稿の並び替え・一時的な欠落で別案に再移行しない。
- 旧原稿単位の読了は1つの代表に保全し、全別案を読了にしない。日時は `null` のまま「以前の読了・日時不明」と表示する。
- コピーは元 eventId・日時・全文を保存する。`copied()` で再登録せず、旧100件＋新100件の移行後や次のコピーでも切り捨てない。
- 旧ページの scroll / offset は新本文へ移さない。選択原稿は新側が未設定の時だけ継承し、font / quiet / focus / haptic も未設定時だけ継承する。
- 未取得の原稿は次の取得時に再照合。移行済みという一括完了印は使わず、書込失敗は再試行できる。保存失敗警告は既存のものを使う。
- 別タブの原稿・印・設定の変更を通知し、利用者が反映すると再同期する。
- 旧 `cc-reading-export-v1` は既存の読み込みプレビューから受け入れる。元原稿、読了の日時不明、コピー全文を保存し、繰り返す時も同じバックアップ原稿IDを使う。

## 検証

`tests/legacy-reading.test.cjs` は旧のみ、新優先、媒体・IDの区別、複数案、再実行、並び替え、不正JSON、容量不足、別タブ、200件の履歴、旧バックアップを検証する。

`scripts/unified-castle-browser.cjs` は実ローダーに隔離したテストデータを渡し、390 / 1440px で classic、キーボード、外部サービス後、再読込、管理画面と読書機能の集約を確認する。既存の操作・マップ・場面・全画面回帰も維持する。
